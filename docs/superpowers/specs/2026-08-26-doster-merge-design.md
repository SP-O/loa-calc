# 도스터 합체 연출 — 설계 문서

- 작성일: 2026-08-26
- 상태: 구현 완료 (검증까지, 배포 대기)
- 대상 파일: `assets/easter-egg.js`, `assets/easter-egg.css`

## 1. 목적 / 범위

푸터 이스터에그에 **이스터에그 속 이스터에그**를 하나 더 심는 것.
도스터가 여러 마리 쌓인 자리에 새 도스터가 떨어지면, 낮은 확률로 서로 뭉쳐
큰 도스터 하나가 되었다가 잠시 뒤 터지면서 도로 흩어진다.

**영구 합체가 아님.** 도스터 하나 = 접속자 하나라는 대응이 이 기능의 존재 이유이고,
영구히 합치면 `ee-mine` 식별·도망 동기화·퇴장 처리가 전부 무너진다.
합체는 수명이 있는 **연출**이며, 원래 도스터는 잠들어 있다가 그대로 돌아온다.

**로컬 전용.** Firebase에 합체 상태를 쓰지 않는다. 화면마다 다르게 보이지만
그게 이 기능의 성격에 맞고, 공유 쓰기 필드를 늘리면 보안 규칙과 악용 여지가 함께 늘어난다.

## 2. 상태 모델

기존 `dosters` Map은 구조를 바꾸지 않는다. `blobs` Map을 따로 얹는다.

```
dosters: key    -> { body, el, inner, type, landed, fleeing, blobId?, ... }   // 기존 + blobId
blobs:   blobId -> { body, el, inner, memberKeys[], type, clicks, dieAt, remainMs, idleTimer }
```

합체될 때 멤버 도스터는 **지우지 않고 재운다.**

| 대상 | 처리 |
|---|---|
| 물리 바디 | 월드에서 제거 후 `d.body = null` |
| DOM | `d.el.style.display = 'none'` |
| 표식 | `d.blobId = blobId` |
| `dosters` Map | **그대로 남김** |

Map에 남기는 것이 핵심. 퇴장·도망 처리가 계속 key로 대상을 찾을 수 있고,
`d.body = null` 하나로 기존 가드 5곳이 자동으로 걸러진다.

| 위치 | 기존 가드 | 결과 |
|---|---|---|
| `syncDosterPositions` | `if (!d.body \|\| !d.el) return;` | 통과 |
| `handleGlobalMouseMove` | `if (!d.body \|\| d.fleeing) return;` | 통과 |
| `triggerCharacterJump` | `if (!d.body \|\| !d.landed ...) return;` | 통과 |
| `schedulePosture` | `if (!b \|\| ...) return;` | 통과 |
| `handleCollisions` | `p.bodyA.dosterKey` 없음 | 통과 |
| `triggerFleeAnimation` | `d.body`를 보지 않음 | **수정 필요 (6-2)** |

물리 코드 본체는 건드리지 않는다.

## 3. 합체 판정

> **구현 중 실측으로 바뀐 부분** (2026-08-26)
> 도스터는 쌓이지 않고 **한 줄로 늘어선다.** 스테이지 1100px에 도스터 10마리 안팎이면
> 평균 간격이 73px이라 서로 닿지 않는다. 그리고 착지 시점엔 무리가 아직 만들어져 있지 않다
> (최종 배치엔 4마리 무리가 있어도, 착지 순간의 이웃 수는 `1,1,1,2,1,2,2,2,4,2`).
> 그래서 **반경 60→90px**, **최소 문턱 4→3마리**, **중심 후보를 주변 도스터까지 확장**했다.

**시점** — 도스터가 잠들어 `landed`가 붙는 그 순간, 한 번만. (`syncDosterPositions`의
`sleeping && !d.landed` 분기) 매 프레임 그룹 판정을 돌리지 않는다.

잭팟(`triggerCharacterJump`)은 `landed`를 풀었다가 다시 붙이므로 **판정이 한 번 더 열린다.**
의도된 동작이다 — 계산 결과가 잘 나와 잭팟이 터진 직후는 사용자가 화면을 보고 있는 몇 안 되는 순간이다.

**중심 후보** — 착지한 도스터 자신뿐 아니라 **사정거리 안의 다른 도스터도 중심으로 놓고** 무리를 세어,
그중 가장 큰 것을 고른다. 자신만 보면 "빽빽한 자리에 정확히 떨어져야" 걸려 거의 일어나지 않는다.
실제로 일어나는 일은 새로 앉으면서 옆쪽 무리를 완성하는 쪽이다.
착지한 도스터가 뽑힌 목록에서 잘려 나가면 인과가 안 보이므로 가장 먼 하나와 바꿔 넣는다.

**후보 필터** — `body != null` && `blobId` 없음 && `!fleeing` && `landed`.
blob과 이미 blob에 속한 도스터는 제외한다.

**반경** — 화면 기준 90px (`toLocal(90)`으로 환산). 한 줄로 서므로 양옆 두 칸까지 닿아야 한다.
60px은 한 칸(양옆 1마리, 최대 3)만 잡혀 실측에서 5마리 문턱이 **0곳**이었다.

**굴림** — 무리 크기를 `k`라 할 때

| 조건 | 확률 | 합칠 마리 | 크기 |
|---|---|---|---|
| `k >= 5` | 55% | 가까운 5마리 | 89px |
| `k == 4` | 35% | 4마리 | 80px |
| `k == 3` | 18% | 3마리 | 69px |
| `k <= 2` | — | — | — |

`k`가 5를 넘어도 **가까운 5마리까지만** 합친다(물리 바디 중심 간 거리 기준).
크기는 늘 세 값 중 하나다. 세 문턱은 크기 변화가 아니라 **빈도 조절**이 목적이고,
확률이 커질수록 실제로는 **큰 합체가 더 자주** 나온다(실측 적중 5회의 내역이 3·4·4·5·5).

**blob은 한 번에 하나만.** 이미 blob이 있거나 흡입 연출이 진행 중이면 판정 자체를 건너뛴다.

**터진 자리는 잠시 쉰다.** 분해는 합체 조건을 그대로 만들어 낸다 — 조각이 한 점에서 튀어
같은 자리 근처에 다시 앉으므로, 착지하는 순간 이미 빽빽한 무리다. 게다가 4~5마리가 각자
굴림을 하니 한 번이라도 걸릴 확률이 `1-(1-0.35)^4 ≈ 82%`다.
실측으로 **4/4 전부, 터진 뒤 1.0~2.2초 만에 재합체**했다(추가 접속자 없이).

| 가드 | 값 | 대상 |
|---|---|---|
| `MERGE_REST_MS` | 9000 | 방금 터진 조각을 무리 계산에서 통째로 제외 (중심·구성원·이웃 모두) |
| `MERGE_QUIET_MS` | 2500 | 폭풍에 밀린 주변 도스터가 자리 잡을 때까지 아무도 뭉치지 않는다 |

**확률을 낮추는 것은 답이 아니다** — 그러면 첫 합체까지 드물어진다. 문제는 확률이 아니라
터진 자리가 곧바로 조건을 만족하는 것이므로 거기만 막는다.
가드별 계수 결과 실제 비용은 분해 후 착지의 약 16%이고, 조각 휴식이 본질적 방어다
(전체 대기를 3000ms로 뒀을 때 착지의 38%를 먹는 것으로 보였으나,
그 측정은 라운드마다 `clearAll` 이 분해를 일으킨 오염이었다. 실제로는 분해가 방문당 한 번뿐이라
비용이 거의 없다. 1200ms 로 줄였더니 폭풍에 밀린 주변끼리 1.8초 만에 뭉치는 경우가 남아 2500ms 로 확정.
도스터 45마리(실전의 4배 밀도)에서 4/4 재합체 없음).

**실측 빈도** — 12마리가 순차 낙하하는 진입 버스트를 6회 재현해 **방문당 0.83회**,
6회 중 5회는 최소 한 번 합체했다.

**실패 연출** — `k >= 3`인데 확률을 놓치면, **합쳐졌을 대상 도스터들**(k>=5면 가까운 5마리, k==4면 4마리)이
서로를 향해 잠깐 기울었다 돌아온다.
확률 규칙이 읽히게 하는 장치. **최소 3초 간격**으로 제한한다(진입 직후 연달아 나오면 시끄럽다).
안쪽 img의 CSS 변형만 쓰고 물리는 건드리지 않는다.

## 4. 연출

**합체 (총 930ms)** — 프레임 단위 실측으로 박자를 다시 잡았다.

| 구간 | 시간 | 내용 |
|---|---|---|
| 예비 동작 | 흡입의 앞 22% | 중심 반대쪽으로 살짝 물러나며 6% 커진다 |
| 흡입 | 480ms | 중심으로 빨려들며 40%까지 줄고, 감기듯 30~55도 돈다 |
| **눌린 채 버티기** | **90ms** | 멤버가 사라지는 **같은 프레임**에 12~16px 짜리 눌린 공이 나타나 버틴다 |
| 팝인 | 360ms | 눌린 공이 부풀어 오르며 오버슛 뒤 100%로 정착 |

**정지 구간에 아무것도 두지 않으면 "비트"가 아니라 "빈틈"이 된다.**
초기 구현은 멤버를 숨기고 90ms 뒤에 blob 을 만들었는데, 실측 결과 그 구간 내내
화면이 완전히 비어 눈이 따라갈 대상이 사라졌다. 눌린 공을 같은 프레임에 띄워 해결했다
(빈 프레임 0 확인).

- 위치·종류(a/b)는 **새로 착지한 도스터**를 따른다. 파고들어 뭉친 주체이므로.
- 멤버에 내 key가 있으면 `ee-mine`을 붙이고, 합쳐지는 순간 **금색으로 한 번 확 밝아졌다**
  평상 글로우로 가라앉는다. 은은한 그림자만으로는 "내 것이 섞였다"가 안 읽힌다.
- 물리 바디는 기존 도스터와 같은 비율로 키운다 — `toLocal(DOSTER_PHYS_R) * 1.7 * sqrt(n)`,
  높이 0.72배, `chamfer` 동일. 밀도가 같으므로 질량은 자연히 `n`배가 된다.
- 멤버가 빠진 자리는 비므로, 옆·위 도스터가 물리적으로 흘러 들어간다(별도 구현 없음).

**클릭** — 쿨다운 없음. blob은 Firebase를 거치지 않으므로 기존 도망의 3초 쿨다운이 불필요하다.

`.easter-stage`가 `pointer-events: none`이므로 **blob 요소에 `pointer-events: auto`와
`cursor: pointer`를 처음부터 준다.** 도스터는 `.landed`가 붙어야 열리는데, blob은
이미 자리 잡은 도스터들로 만들어지므로 기다릴 이유가 없다.
(과거에 정확히 이 설정이 빠져 "눌러도 안 되는 도스터" 버그가 났다.)

| 클릭 | 반응 |
|---|---|
| 1번 | 살짝 갸우뚱 |
| 2번 | 크게 부르르 |
| 3번 | 펑 (5절) |

안쪽 img의 CSS 변형만 쓴다. 물리로 흔들면 아래 깔린 도스터 더미가 흐트러진다.
`clicks`는 blob 수명 동안 유지되며 리셋하지 않는다.

**수명** — 합체 애니메이션이 끝난 시점부터 15초. 단, **보고 있을 때만 흐른다.**

```
수명이 흐르는 조건 = 탭이 보임  &&  스테이지가 뷰포트 안에 있음
```

이게 이 설계에서 가장 중요한 부분이다. 합체가 일어나는 시점과 사람이 보는 시점이 어긋나기 때문이다.

| 시각 | 무슨 일 | 사용자는 |
|---|---|---|
| t=0.5초 | Firebase 접속, 도스터 우수수 낙하 | 계산기 상단을 보는 중 |
| t=2~5초 | 착지 → **합체 판정 대부분이 여기서 일어남** | 여전히 상단 |
| 이후 | 새 착지는 몇 분에 한 번 | 언젠가 스크롤을 내림 |

즉 그냥 두면 **합체는 아무도 안 보는 사이에 일어나고 15초 뒤 혼자 터진다.**
빈도를 아무리 올려도 관측되는 횟수는 0에 가깝다.

수명을 멈춰 두면, 진입 직후 뭉친 큰 도스터가 **사용자가 푸터까지 스크롤을 내리는 그 순간까지
그대로 앉아 기다린다.** 눈에 들어오고, 눌러 보고, 터진다 — 기능 전체가 보고 있는 동안 일어난다.

구현은 `handleVisibility`(탭)와 `IntersectionObserver`(스크롤) 두 신호를 하나로 합쳐,
남은 시간(`remainMs`)을 보관했다 재개하는 방식. 탭 숨김만 처리하려던 것을 한 조건 넓히는 것뿐이다.

**idle** — blob 전용. 전역 idle 루프(10~15초 간격)에서는 제외한다.
수명이 15초라 그냥 얹으면 볼 기회가 거의 없다. blob 자체 타이머로 생성 후 약 4초에 한 번,
느리고 큰 한 동작. 기존 3종(0.5~0.8초짜리 잔망스러운 갸우뚱)을 쓰면 5배 큰 놈이 가벼워 보인다.

## 5. 분해

트리거는 넷, 함수는 `dissolve(blobId)` 하나로 모은다.

| 트리거 | 거는 곳 |
|---|---|
| 세 번째 클릭 | blob 클릭 핸들러 |
| 수명 15초 만료 | blob 타이머 |
| 멤버의 접속자 퇴장 | `removeCharacter` |
| 멤버가 도망당함 | `triggerFleeAnimation` — **분해 먼저, 도망 나중** |

**동작 (총 390ms)** — 부풀기와 터짐을 **두 애니메이션으로 분리**한다.
한 덩어리로 두면 앞 120ms 동안 11%밖에 안 커져 지각 문턱 아래로 떨어지고,
결과적으로 "부풀었다 펑"이 아니라 "그냥 사라진다"로 보인다(실측).

| 구간 | 시간 | 내용 |
|---|---|---|
| 부풀기 | 280ms | 100% → 128% → **114%로 움츠림** |
| 터짐 | 80ms | 114% → 195% + 페이드아웃 |

**끝에서 움츠리지 않으면 한 번의 긴 팽창으로 읽힌다.** 초기 구현은 부풀기와 터짐이
같은 방향으로만 이어져(실측 433 → 527 → 682px) "부풀었다 펑"이 아니라 계속 커지다 사라지는
것처럼 보였다. 마지막 18%에서 −14%p 되돌려 예비 동작을 만들었다.

1. 물리 바디를 빼고 `blobs`에서 지운다(수명·합체 게이트가 곧바로 풀린다).
2. **조각은 터지는 순간과 겹쳐 나온다.** 껍데기가 다 사라진 뒤 내보내면
   "터져 나온다"가 아니라 "사라지고 나타난다"로 보인다.
3. 살아남은 멤버만 복원한다 — 새 바디를 만들고 안쪽 img를 45%에서 100%로 부풀린다.
4. **터지는 각도는 위쪽 부채꼴(140도)**로 펼친다. 360도 균등 분배는 절반이 위아래로만
   밀려 제자리에 남는다(실측 3 · 87 · 18 · 5 · 59px).
   세로 성분은 `BURST_RISE = 0.62`로 깎는다 — 그대로 두면 푸터 위 296px 까지 솟아 본문을 덮는다.
5. **힘이 아니라 속도를 직접 준다**(`setVelocity`). `applyForce` 는 한 스텝만 작용하고
   질량에 나뉘어 결과가 간접적이다. 초기 속도 `BURST_SPEED = 7.5` px/스텝(±25%).
6. **조각을 굴린다**(`BURST_SPIN = 0.28`). 각속도가 0이면 터져 나가는데 자세가 뻣뻣해
   폭발로 안 보인다. 나가는 방향으로 굴린다.
7. **주변 도스터를 밀어낸다**(`blastNearby`, 반경 130px, 거리 감쇠).
   멤버만 튀고 옆 도스터가 가만히 있으면 "펑" 이 반쯤 죽는다.
   `landed` 는 떼지 않는다 — 떼면 그동안 클릭이 막힌다(예전 버그).
8. 조각의 등장 연출은 **작게 시작해 자라나는 것이 아니라** 진행 방향으로 한 번 늘어났다 돌아온다.
   작게 시작하면 "튀어나온다"가 아니라 "생겨난다"로 읽힌다.
5. 나간 사람 것은 이미 `removeCharacter`가 Map에서 지웠으므로 자동으로 빠진다.

**멤버가 하나도 안 남는 경우** — 마지막 한 명이 나가면서 분해가 걸리면 아무것도 복원되지 않고
blob만 사라진다. 드물고, 동작상 문제 없다.

## 6-B. 배포 후 발견 (2026-08-26)

**도스터가 푸터 선 위로 떠서 앉는 버그.** 라이브에서 사용자가 발견.

기울어진 채 잠든 바디는 모서리로 서 있어 중심이 높다. `schedulePosture` 가 각도만 0으로
되돌리고 위치는 건드리지 않으므로, **그 높이에 그대로 박제된다.** 잠든 바디라 중력도 당기지 않는다.

실측 (자세 교정 전 → 후):

| 각도 | bottom |
|---|---|
| −102.2° → 0° | 5.4 → **5.4** |
| −78.1° → 0° | 30.2 → **30.2** |
| 89.7° → 0° | 4.7 → **4.7** |

계산과도 맞는다 — 모서리가 둥근 34×24.5 사각형이 −102° 로 누우면 중심~최저점이 17.8px,
0° 면 12.25px, 차이 5.6px (실측 5.4px).

**고침** — `setAngleGrounded()` 를 두어 각도를 바꿀 때 **최저점을 제자리에 두고 중심만 내린다.**
바닥이든 다른 도스터 위든 얹혀 있던 자리를 그대로 유지한다.

```
lowestSpan(body, angle) = |(halfW-r)·sin| + |(halfH-r)·cos| + r      (r = chamfer 반지름)
내릴 거리 = lowestSpan(현재 각도) - lowestSpan(새 각도)
```

결과: 0.5px 넘게 뜬 도스터 **9/11 → 0/10**, 층층이 쌓인 것도 아래로 파고들지 않음(0건).
도스터 PNG 는 아래 투명 여백이 0% 라 `bottom: 0` 이면 발이 정확히 선에 놓인다(확인함).

## 7. 부수 개선 (설계에 포함)

**7-1. 커서 밀기에 무게 반영** — 기존 코드의 문제.

```js
var power = (1 - dist / reach) * PUSH_FORCE * d.body.mass;
```

힘에 질량을 곱해 **가속도가 질량과 무관**해져 있다. 지금은 크기가 다 비슷해 티가 안 나지만,
5배 무거운 blob이 솜털처럼 밀리면 무게감이 무너진다. **질량 곱을 제거**한다.
기존 밀도 개체차(0.85~1.15배)도 비로소 화면에 드러난다.

잭팟 점프(`triggerCharacterJump`)는 이미 질량을 곱하지 않아 올바르다. 건드리지 않는다.

**7-2. 합체 실패 연출** — 3절 참조.

**7-3. 내 도스터 합류 순간 반짝** — 4절 참조.
